# ws API items and their ventijs modules

Every item named in the vendored reference at [ventijs.md](ventijs.md), the
module that implements it, and its status. The status vocabulary is defined in
[compliance.md](compliance.md). The two socket routes are named throughout:

- **codec route**: the `WebSocketServer` upgrade route. It builds a Node `http.Server`, answers the
  `upgrade` request in `src/compat/server/upgrade.ts`, adopts the resulting
  `Duplex` in `src/compat/socket/attach.ts`, and hands its bytes to the Zig frame
  codec in `src/compat/socket/codec-inbound.ts`.
- **engine route**: a socket created by `attachNativeSocket` in
  `src/compat/socket/attach.ts`, reached from `src/binding/socket.ts` and the
  engine. The engine parses frames in Zig; JavaScript sees only lifecycle
  events.

| ------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `host`, `port`, `backlog`, `server`, `noServer`, `path` | `src/compat/options/server.ts`                                                         | `done`        | Exactly one listen target, or the `ws` `TypeError`; `server/close.ts` reads them                                                                                                                                                                                                                                                                                             |
| `clientTracking`                                        | `src/compat/server/{accept,close,clients}.ts`                                          | `done`        | Governs tracking and server `close`                                                                                                                                                                                                                                                                                                                                          |
| `verifyClient`, `handleProtocols`, `WebSocket`          | `src/compat/server/{handshake,upgrade,accept}.ts`                                      | `done`        | Hardened beyond `ws`; see the divergence note in `COMPATIBILITY.md`                                                                                                                                                                                                                                                                                                          |
| `autoPong`                                              | `src/compat/options/{server,client}.ts`, `src/compat/socket/{accept,codec-inbound}.ts` | `done`        | Read on both routes, and copied from the server onto each accepted socket. The codec answers a ping before the application hears about it, which section 5.5.2 requires, and `autoPong: false` suppresses the reply for an application that answers itself                                                                                                                   |
| `allowSynchronousEvents`                                | `src/compat/socket/codec-deferral.ts`                                                  | `done`        | `false` pauses the _parse_, not the dispatch, so a `close` behind the messages in one read is delivered after them. One event per tick, which is what `ws` delivers                                                                                                                                                                                                          |     |
| `maxPayload`                                            | `src/compat/options/{server,client}.ts`, `src/compat/socket/codec-handle.ts`           | `done`        | Enforced per connection, at the option's value, on both routes. `0` means no limit, as in `ws`. A peer over it is closed with 1009. The codec's buffers grow into the ceiling on demand, so the cost tracks what a connection sends rather than what it is allowed to send                                                                                                   |
| `skipUTF8Validation`                                    | `src/compat/options/{server,client}.ts`, `src/engine/codec/utf8.zig`                   | `done`        | One flag at `codec_create` and one branch in the byte path, because the codec is the validator. Declared by neither `ws` nor `@types/ws`, so a TypeScript caller casts                                                                                                                                                                                                       |
| `perMessageDeflate`                                     | `src/compat/extensions/`, `src/engine/codec/{deflate,inflate,rsv1}.zig`                | `done`        | RFC 7692 on both routes. The engine's own libdeflate, so a message compressed on either route is readable on the other. Both directions answer `server_no_context_takeover; client_no_context_takeover` unconditionally, because the compressor is one-shot; a `*_max_window_bits` below 15 is declined rather than accepted and ignored                                     |
| `closeTimeout`                                          | `src/compat/socket/codec-close.ts`                                                     | `done`        | A bounded close handshake on both routes. A peer that receives a close frame and never answers one is torn down and reports 1006, rather than holding its transport and codec slot for the life of the process. `@types/ws` declares no such option, so it is read at runtime like `ws` reads it                                                                             |
| `maxFragments`                                          | `src/compat/options/shared.ts`, `src/engine/codec/fragments.zig`                       | `done`        | Enforced per connection, at the option's value, and a peer exceeding it is closed with 1008. `0` means no limit, as in `ws`. The boundary list starts at sixteen entries and grows, so a connection that is never fragmented does not pay for one that is                                                                                                                    |
| `maxBufferedChunks`                                     | `src/compat/server/server.ts`                                                          | `unreachable` | `unreachable` by construction: in `ws` it bounds the receiver's queue of un-decoded socket reads, and ventijs holds at most one read's tail in `state.pendingInput` (`src/compat/socket/codec-inbound.ts:82`), which is already far below the 262144 `ws` defaults to. Echoed on `server.options` at the `ws` default so `Object.keys(server.options)` matches; not enforced |

Option normalisation is covered by `tests/compat/options/{normalization,server,client}.test.ts`
and compared with `ws` by `tests/conformance/options.conformance.test.ts`.

Tests backing the `done` rows above: `tests/compat/socket/socket.test.ts`,
`tests/compat/socket/close.test.ts`, `tests/compat/socket/payload.test.ts`,
`tests/compat/socket/upgrade-route.test.ts`, `tests/compat/events/dom-listeners.test.ts`,

`tests/compat/socket/upgrade-route.test.ts` is the suite for the route a
`WebSocketServer`-produced socket actually takes, which no other file exercised:
it builds a socket with a live transport and no native attachment and pins the
three behaviours that route owns, which are that `close()` reaches `CLOSED`, that
a transport failure arrives as `error` even when an earlier recoverable report
burned the latch, and that `bufferedAmount` does not climb without bound.
